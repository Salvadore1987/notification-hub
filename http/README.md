# HTTP-коллекция

Запросы ко всем REST-эндпоинтам Модуля в формате [JetBrains HTTP Client](https://www.jetbrains.com/help/idea/http-client-in-product-code-editor.html) —
он встроен в IntelliJ IDEA, отдельного плагина не нужно. Каждый запрос снабжён
комментарием: что делает, кому доступен, что обязательно и где легко ошибиться.

Коллекция ничем не собирается и ни на что не влияет: Gradle её не видит, Spotless и
Checkstyle `.http` не трогают.

## Как пользоваться

1. Поднять окружение и приложение:

   ```bash
   docker compose up -d
   ./gradlew :bootstrap:bootRun
   ```

2. Выполнить запросы из `00-auth.http` — они складывают токены в глобальные
   переменные `{{adminToken}}`, `{{operatorToken}}` и так далее, которыми пользуются
   остальные файлы. Токен живёт 15 минут; посыпались `401` — вернитесь и перевыпустите.
3. Дальше — тот файл, который нужен.

**Окружение выбирать не надо.** Значения локального стенда объявлены прямо в начале
каждого файла через `@переменная = значение` — такие переменные подставляются сами и
работают при «No Environment». Файла `http-client.env.json` в коллекции нет намеренно:
порядок приоритета между объявлением в файле и переменной окружения в документации
JetBrains не описан, так что два источника значений давали бы неоднозначность.

Чтобы постучаться в другой контур, поменяйте `@host` (и `@keycloak` в `00-auth.http`)
в начале нужного файла. Обратная сторона решения: область видимости `@`-переменной —
один файл, поэтому `@host` повторяется в пяти файлах, и адрес другого контура придётся
поменять в каждом из тех, что собираетесь запускать.

## Файлы

| Файл | Что внутри |
|---|---|
| `00-auth.http` | токены: `demo`/ADMIN, по одному на роль §10.1, `client_credentials` для системы-источника |
| `10-config.http` | провайдеры, каналы, потоки, политики маршрутизации |
| `20-templates.http` | шаблоны с их workflow и suppression-лист |
| `30-send.http` | отправка из панели, `/api/v1` (сообщения и рассылки), отчёты провайдеров |
| `40-monitoring.http` | сообщения, рассылки, DLQ, статистика, аудит, дашборд |
| `50-admin.http` | kill switch, системные параметры, контракт, actuator |

**`10-config.http` прогоняется сверху вниз на пустой базе** и оставляет настроенный
контур: порядок запросов в нём — это порядок первичной настройки
(провайдер → канал → поток), и переставить его нельзя, потому что `fallbackOrder`
канала ссылается на код провайдера. Идентификаторы (`providerId`, `policyId`,
`batchId`, `messageId`, …) подхватываются из ответов обработчиками, руками их
подставлять не надо.

Сквозной рассказ про то же самое, но словами, — в [`../docs/QUICKSTART-SEND.md`](../docs/QUICKSTART-SEND.md);
настройка через экраны панели — в [`../docs/ADMIN-GUIDE.md`](../docs/ADMIN-GUIDE.md).

Третий способ подачи — Kafka — сюда не помещается: HTTP Client в топик не пишет. Готовые
документы для входящих топиков лежат в соседней коллекции [`../kafka/`](../kafka/README.md).

## Что стоит знать до первого запуска

- **`/api/admin/v1/**` требует токен на любом контуре** — «открытого режима» у панели
  не существует (ADR-0037). `401` это «кто ты», `403` — «тебе нельзя».
- **`/api/v1` локально токена не требует**: `commhub.security.require-source-system-token`
  по умолчанию `false`. В контуре Банка — `true`, и тогда `streamId` сверяется с
  claim'ом токена. В `30-send.http` строка `Authorization` для этого случая оставлена
  закомментированной.
- **`X-Commhub-Reason` жёстко обязателен ровно на двух эндпоинтах** — `POST /send/message`
  и `POST /send/batch`. Везде ещё он необязателен и просто попадает в аудит. Значение —
  percent-encoded UTF-8: значение HTTP-заголовка есть байтовая строка, и кириллица
  иначе не пройдёт. У kill switch обоснование вообще не в заголовке, а в теле.
- **Период `from`/`to`** — ISO-инстант с `Z` (`2026-08-10T00:00:00Z`), голая дата даёт
  400. По умолчанию последние 24 часа, максимум 92 дня; `/dlq` и `/audit` — исключение,
  у них нет ни окна по умолчанию, ни потолка.
- **Поведение фиктивного провайдера задаётся последними двумя цифрами номера**:
  `…00` доставлено, `…01` недоставлено, `…02` ответа нет (ретрай и failover),
  `…03` блокирующий отказ, `…04` адрес непригоден. Номера лежат в окружении как
  `{{msisdnDelivered}}` и далее.
- **Один запрос обязан падать.** В `30-send.http` есть отправка без `X-Commhub-Reason`
  с проверкой на 400 — она подтверждает, что FR-7.3 закрыт контроллером, а не только
  формой панели.

## Секреты

В файлах лежат только демонстрационные логины локального стенда — ровно те же, что и
в `docker/keycloak/commhub-realm.json`. Ничего боевого сюда класть не нужно: для этого
у HTTP Client есть `http-client.private.env.json`, и он добавлен в `.gitignore` именно
затем, чтобы не уехал в репозиторий.
