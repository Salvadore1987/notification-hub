# ADR-0011. Persistence на JdbcClient с рукописными мапперами вместо JPA

| | |
|---|---|
| **Статус** | Принято · реализовано |
| **Дата** | 08.08.2026 |
| **Требования SRS** | AR-02, DB-01, DB-02, DB-05 |
| **Связанные решения** | [ADR-0001](ADR-0001-hexagonal-architecture.md), [ADR-0008](ADR-0008-partitioning-and-retention.md), [ADR-0012](ADR-0012-application-level-encryption.md) |

## Контекст

AR-02 запрещает домену зависеть от JPA. Формально это обходится маппингом «сущность ORM ↔ доменный объект», но
тогда появляется вторая модель, повторяющая первую, и мапперы между ними. Плюс агрегаты собираются через фабрики
и `rehydrate`-строители, проверяющие инварианты, — ни один entity mapper так не умеет: он присваивает поля.

## Решение

Адаптеры персистентности — классы `…PersistenceAdapter` поверх Spring `JdbcClient` с рукописными row-мапперами.
Агрегат восстанавливается через собственные фабрики или `rehydrate`-строители домена. Обоснование записано в
`adapter/out/persistence/package-info.java`.

Сопутствующие правила модуля:

- **`jsonb` идёт через собственный `JsonCodec`** (Jackson 3, `tools.jackson.*` начиная с Boot 4) и явные
  `…Json`-записи — никогда через общий REST-овский `ObjectMapper`: формат хранения и формат API не обязаны
  совпадать и не должны меняться вместе.
- **Мгновения биндятся как `OffsetDateTime` в UTC** — у драйвера нет маппинга для `Instant`.
- **Миграции только Flyway**, схема `comm_hub`, имена `V<n>__<snake_case>.sql`.

## Альтернативы

- **Spring Data JPA с отдельными entity-классами.** Даёт «бесплатные» репозитории и забирает контроль над SQL там,
  где он нужнее всего: партиционированные таблицы, `FOR UPDATE SKIP LOCKED` в релее outbox, `ON CONFLICT DO NOTHING`
  в реестре suppression, GIN-поиск по получателю. Плюс вторая модель и её мапперы.
- **JPA прямо на доменных классах.** Нарушает AR-02, тащит в домен аннотации, требует пустых конструкторов и
  изменяемых полей — то есть ломает инварианты, ради которых домен и написан.
- **jOOQ.** Хорошо ложится на задачу, но добавляет генерацию кода из схемы в сборку и ещё одну лицензию к
  согласованию; выигрыш над `JdbcClient` на нашем объёме запросов невелик.

## Последствия

**Положительные.** SQL виден целиком в том месте, где он выполняется, — это принципиально для запросов панели,
где план запроса и попадание в партицию определяют, откроется экран или нет. Нет ленивой загрузки, нет N+1 «из
ниоткуда», нет сессии, живущей дольше транзакции. Шифрование контента вставляется в один слой кодека (ADR-0012).

**Цена.** Маппер на агрегат пишется руками, и при добавлении поля его нужно не забыть в трёх местах: SQL,
маппер, миграция. Это компенсируется тем, что каждое из трёх мест покрыто интеграционным тестом на реальной
PostgreSQL (Testcontainers), а не моком.

## Как нарушение будет замечено

ArchUnit запрещает persistence-аннотации в домене. `FlywayMigrationIT` собирает схему с нуля. Интеграционные
тесты `AbstractPersistenceIT` гоняют каждый адаптер против настоящей базы — забытое поле в маппере падает там,
а не в проде.
