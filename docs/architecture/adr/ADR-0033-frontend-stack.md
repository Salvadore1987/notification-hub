## Контекст

§3.1 и UI-01 задают React 18 + TypeScript на Vite и оставляют выбор UI-kit между Ant Design и MUI за согласованием
с Банком. Панель — это двенадцать разделов, состоящих в основном из таблиц, форм и фильтров, работающих с
большими списками.

## Решение

**Ant Design 5** (выбор согласован 09.08.2026): у него из коробки есть то, из чего состоит эта панель — таблицы
с серверной пагинацией и сортировкой, формы, `DatePicker` с диапазонами, локали. Панель живёт в `web/` и
**намеренно вне Gradle**: у неё свой цикл сборки и свой менеджер пакетов.

**Конфигурация развёртывания читается до первого рендера** — `public/config.json`: issuer и clientId OIDC,
`rolesClaim` (зеркалит `commhub.security.roles-claim`), отображение групп SSO в роли §10.1. Пустой issuer —
не режим работы, а ошибка настройки контура: панель показывает «не настроена» и не пускает внутрь (ADR-0037,
заменивший открытый режим ADR-0031). Собранный артефакт один и тот же для всех контуров — контур задаётся файлом,
а не пересборкой.

**Аутентификация — Code + PKCE** через `oidc-client-ts`, токены в `sessionStorage`, тихое продление.
`src/auth/roles.ts` зеркалит `AdminAuthority`, а разделы §11.2 объявлены **один раз** в
`src/layout/navigation.tsx`: меню, маршруты и ограничение доступа берутся из этого списка. Настоящим решением
о доступе остаётся `@PreAuthorize` на backend.

**Типы API генерируются из контракта** (`npm run generate:api`, результат коммитится); middleware `openapi-fetch`
превращает любой не-2xx в один `ApiError`, несущий `problem+json` и разобранный `Retry-After`. Расхождение
панели с BFF становится ошибкой компиляции TypeScript.

**Общие решения экранов.** `ServerTable` делает серверную пагинацию и сортировку и виртуализацию по высоте, а
фильтры принадлежат экрану и замыкаются в `fetchPage`. `maskMsisdn`/`maskEmail` зеркалят `Masking.java` — но
только для значений, которые ввёл сам оператор; что видит роль в данных, решает `AdminMasking` на сервере.
i18n RU/UZ/EN (RU по умолчанию и как запасной), часовой пояс отображения фиксирован `Asia/Tashkent` над
хранением в UTC (`src/shared/time.ts`).

**Долги фазы 15 видны на экранах намеренно**: карточка батча показывает нулевой прогресс, пока у
`Batch.registerSent` не появятся вызовы. Чинить нужно backend, а не экраны.

## Альтернативы

- **MUI.** Равноценен по возможностям; Ant Design выбран из-за более близкой к задаче таблицы и меньшего объёма
  собственного кода под серверную пагинацию.
- **Собрать конфигурацию в бандл на этапе сборки.** Требует отдельного артефакта на контур — то есть
  пересборки ради смены issuer.
- **Писать типы API руками.** Расхождение с BFF перестаёт быть ошибкой компиляции и становится дефектом в проде.
- **Включить `web/` в Gradle.** Смешивает два цикла сборки; Gradle начинает зависеть от Node, а сборка backend —
  от установленного npm.

## Последствия

**Положительные.** Один артефакт на все контуры. Правки контракта BFF ловятся компилятором. Разделы, меню и
маршруты не расходятся — они из одного списка.

**Цена.** Сгенерированные типы коммитятся, значит их нужно перегенерировать при правке контракта — забытая
генерация видна как расхождение в дифе. Зеркала (`roles.ts`, `maskMsisdn`) требуют синхронизации с backend;
обе покрыты тестами, сверяющими списки с генерированной схемой контракта.

## Как нарушение будет замечено

Vitest: пуре-модули и компоненты, чья поломка видна на каждом экране (`ServerTable`, `useReasonPrompt`,
`RequireSection`, меню по ролям, DLQ, тестовая отправка). Стаб BFF (`src/test/api.ts`) записывает отправленное,
поэтому один тест проверяет и запрос, и то, что увидел оператор. Отдельный тест сверяет три словаря i18n между
собой и с ключами, которые экраны реально спрашивают у `t()`, а списки перечислений в `shared/labels.ts` — со
схемой генерированного контракта: новый статус §6.3 не должен молча выпасть из фильтра.
