# ADR-0010. Один Gradle-модуль на адаптер; координаты выводятся из пути проекта

| | |
|---|---|
| **Статус** | Принято · реализовано |
| **Дата** | 09.08.2026 |
| **Требования SRS** | AR-01, AR-03, AR-04 |
| **Связанные решения** | [ADR-0001](ADR-0001-hexagonal-architecture.md) |

## Контекст

Границы гексагона проверял ArchUnit по пакетам. Это ловит нарушение слоя, но не ловит нарушение **между
адаптерами**: адаптер Playmobile мог сослаться на классы адаптера persistence, и ни один тест бы не возразил —
оба лежат в `adapter`. Между тем AR-04 требует, чтобы добавление провайдера не задевало ничего, кроме нового кода.

## Решение

Каждый адаптер — отдельный Gradle-модуль, путь проекта повторяет каталог:
`:adapter:in:rest`, `:adapter:out:persistence`, `:adapter:out:provider:playmobile` (поэтому `projectDir` нигде
не задаётся). Java-пакеты при разделении не менялись — ArchUnit по-прежнему проверяет слои, а Gradle теперь
проверяет рёбра между адаптерами.

`:adapter` — модуль-агрегатор с `api`-зависимостями на все адаптеры: `./gradlew :adapter:build` собирает слой,
а `bootstrap` зависит от одного проекта, а не от двадцати двух (композиционному корню по определению нужны все).

Добавление провайдера = каталог + `build.gradle.kts` + строка в `settings.gradle.kts` + строка в
`adapter/build.gradle.kts`.

**Две вещи в корневой сборке существуют только из-за вложенности путей и не подлежат «упрощению»:**

1. **`group` выводится из пути проекта** (`uz.hamkorbank.commhub` + путь родителя).
2. **`archivesName` — полный путь** (`adapter-in-kafka`).

Причина: имя Gradle-модуля — это последний сегмент пути, поэтому `:adapter:in:kafka` и `:adapter:out:kafka` оба
называются `kafka`. При общей группе их координаты `group:name` совпадают — и `testFixtures(project(...))` на
один резолвится в другой. При общем имени архива fat jar получает две записи `kafka-0.1.0-SNAPSHOT.jar`: сборка
падает, а под стратегией «берём первый» молча потеряла бы половину одного из адаптеров.

Общая тестовая инфраструктура ездит как `testFixtures`: `AbstractPersistenceIT`/`PostgresSchema`
(`:adapter:out:persistence`), `KafkaBroker` (`:adapter:out:kafka`), `ProviderStubs`/`FixedClock`
(`:adapter:out:provider:support`). Конфигурации `testFixtures` **не наследуют BOM** из корневой сборки — модулю
с фикстурами нужен свой `testFixturesImplementation(platform(libs.spring.boot.bom))`.

## Альтернативы

- **Один модуль `adapter`.** Проще граф, но рёбра между адаптерами не контролируются ничем, кроме внимательности.
- **Модуль на слой (`adapter-in`, `adapter-out`).** Половинчато: провайдеры остаются в общем модуле, и AR-04
  снова держится на честном слове.
- **Плоские имена (`adapter-in-rest` как имя проекта).** Убирает коллизию имён, но разводит структуру каталогов и
  пути проектов — навигация перестаёт быть очевидной.

## Последствия

**Положительные.** Запрещённая зависимость между адаптерами теперь не компилируется. Сборка распараллеливается
лучше, а изменение одного провайдера не пересобирает остальные.

**Цена.** Файлов сборки больше двадцати; появление зависимости требует явной строки. Часть кросс-адаптерных
тестов (`ProviderDocumentationContractTest`, `ProviderRuntimeSettingsTest`) пришлось поселить в `bootstrap` —
единственном модуле, который видит всех.

Отдельные факты графа, которые стоит знать до правки: `WebSecurityConfig` живёт в `bootstrap/config`, потому что
собирает цепочки rest + admin + callback разом — это проводка композиционного корня, и возврат её в любой из трёх
адаптеров воссоздаёт цикл, ради разрыва которого она туда переехала. `:adapter:in:admin` зависит от
`:adapter:in:rest` (карточки сообщения и батча отвечают ровно телом §8.2), от `:adapter:in:importer` (общий
CSV-парсер) и от `:adapter:out:provider:support` (маскирование). Модули провайдеров зависят от
`:adapter:in:callback` только ради интерфейса `ProviderCallbackTranslator`.

## Как нарушение будет замечено

Компилятором: недостающая зависимость — ошибка сборки. `ApplicationContextIT` поднимает контекст с настройками
развёртывания и проверяет, что у каждого driven-порта есть адаптер, — так отсутствие бина перестаёт быть
открытием в проде.
