# ADR-0017. Админ-панель получает собственный API `/api/admin/v1`, а не долю в `/api/v1`

| | |
|---|---|
| **Статус** | Принято · реализовано |
| **Дата** | 09.08.2026 |
| **Требования SRS** | §11.2, UI-02, SEC-02, SEC-03, SEC-08, FR-7.1 |
| **Связанные решения** | [ADR-0018](ADR-0018-admin-masking-and-paging.md), [ADR-0031](ADR-0031-security-off-by-default.md), [ADR-0033](ADR-0033-frontend-stack.md) |

## Контекст

Панели нужны почти те же данные, что и системам-источникам: карточка сообщения, карточка батча, список рассылок.
Соблазн — переиспользовать `/api/v1` и добавить туда админские операции. Но `/api/v1` — опубликованный контракт
§8.2, под который интегрируются системы Банка, а панель — фронт, который поставляется вместе с backend и меняется
вместе с ним.

## Решение

Отдельный API `/api/admin/v1` в модуле `:adapter:in:admin`, один контроллер на раздел §11.2.

- **Контракт §8.2 не двигается под нужды панели.** Экраны — наш собственный BFF, его можно менять в одном релизе
  с фронтом.
- **Цепочка безопасности SEC-02 применяется к префиксу**, а не к списку endpoint-ов, который кто-то должен не
  забыть расширить.
- **Карточка сообщения и карточка батча отвечают ровно телом §8.2** (модуль `:adapter:in:admin` зависит от
  `:adapter:in:rest` ради dto и мапперов). Тогда экран, который оператор читает во время инцидента, и ответ,
  который опросила система Банка, — это один и тот же документ, и спорить не о чем.
- **Переход от батча к его сообщениям — это список сообщений с фильтром `batchId`**, а не вложенный endpoint:
  та же пагинация, то же маскирование, та же запись SEC-08.

Три решения живут в этом слое и больше нигде: кто что может вызывать (`@PreAuthorize` из `AdminAuthority`),
сколько адреса видит роль (`AdminMasking`), и чему равен период по умолчанию (`AdminPeriod`) — см. ADR-0018.

## Альтернативы

- **Общий API с ролевым доступом.** Публичный контракт начинает зависеть от нужд одной SPA и обрастает полями,
  которые системам-источникам не нужны и которые нельзя убрать после публикации.
- **GraphQL для панели.** Решает задачу выборки полей и добавляет второй способ описывать контракт, второй способ
  авторизации и незнакомый инструмент в эксплуатацию.
- **Прямой доступ панели к БД.** Прямо запрещён UI-02 и уничтожает SEC-08.

## Последствия

**Положительные.** Экраны развиваются, не задевая интеграции Банка. Правила доступа применяются к префиксу.
Инцидентный разбор ведётся по тому же документу, который видит система-источник.

**Цена.** Часть кода отвечает похожими структурами дважды; это ограничено переиспользованием dto §8.2 там, где
структура должна совпадать буквально. Модуль `admin` зависит от `rest`, `importer` и `provider:support` —
зависимости явные и обоснованные (ADR-0010).

## Как нарушение будет замечено

Появление админской операции под `/api/v1` видно на ревью и ломает разделение цепочек безопасности:
`WebSecurityConfig` собирает три цепочки по префиксам, и «чужой» endpoint попадает не в свою.
