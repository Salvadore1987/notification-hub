# Записи архитектурных решений (ADR)

Каждый файл фиксирует **одно** решение: контекст, само решение, рассмотренные альтернативы, последствия и то,
**как нарушение будет замечено**. Последний раздел обязателен: решение, нарушение которого никто не заметит,
через полгода перестаёт быть решением.

- Решения из §3.2 SRS (`AD-01…AD-08`) — это ADR-0001…ADR-0008.
- Остальное — решения, принятые при реализации; они зафиксированы ретроспективно по факту готовых фаз 1–18
  и отмечены датами 08–09.08.2026.

Статусы: **принято** · **вне объёма** (решение не делать) · **временное** (с условием пересмотра) ·
**заменено** (ADR, отменённый более поздним). Отменённые записи не удаляются: причина, по которой решение было
верным раньше, объясняет, почему его меняют сейчас.

## Как добавить ADR

1. Скопировать [`ADR-0000-template.md`](ADR-0000-template.md), взять следующий свободный номер.
2. Заполнить разделы. Раздел «Как нарушение будет замечено» — не формальность: если ответа нет, решение,
   скорее всего, ещё не дозрело до записи.
3. Добавить строку в таблицу этого файла.
4. Если новое решение отменяет прежнее — пометить прежнее статусом **заменено** и сослаться на новое.
   Удалять не нужно.
