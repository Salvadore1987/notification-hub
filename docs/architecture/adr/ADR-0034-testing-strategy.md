# ADR-0034. Тесты разделены по вопросу, на который отвечают

| | |
|---|---|
| **Статус** | Принято · реализовано |
| **Дата** | 09.08.2026 |
| **Требования SRS** | QA-01…QA-08, NF-08, AR-02, AR-03 |
| **Связанные решения** | [ADR-0013](ADR-0013-no-ci-in-repo.md), [ADR-0010](ADR-0010-module-per-adapter.md), [ADR-0006](ADR-0006-canonical-status-model.md) |

## Контекст

К концу разработки в проекте 881 unit-тест и 150 интеграционных. Такой объём становится обузой, если тесты
организованы «по классам»: непонятно, где искать проверку конкретного правила, и каждое изменение задевает
десятки файлов. Поэтому уровни разделены по **вопросу**, а не по структуре кода.

## Решение

**Unit — домен и прикладной слой без Spring.** Домен: 291 тест, ~97 % строк. Прикладной слой: 204 теста, ~87 %.
Критическая логика (маршрутизация, дедупликация, статусная машина, сегментация) покрыта прицельно (QA-01). Стиль —
AAA.

**ArchUnit разделён по вопросу** (QA-02):

- `HexagonalArchitectureTest` — «может ли этот слой видеть тот»: слои, AR-02 и правило AR-04 о том, что никто вне
  пакета провайдера не имеет права называть его классы;
- `LayerConventionsTest` — «на своём ли месте лежит этот класс»: имена, records против классов, `mapper/`,
  `handlers/`, отсутствие полевой инъекции, отсутствие логгера и транспортных типов в `application`, отсутствие
  часов в домене.

**Модуль `bootstrap` владеет тестами, которым нужен целый Модуль**: `HubTestContainers` (одна PostgreSQL и один
брокер на JVM, мигрируемые самим приложением), `HubConfiguration` (потоки, канал, провайдеры и политика
маршрутизации пишутся **через репозитории, а не SQL**), `ProviderStub` (один WireMock).

**`ApplicationContextIT` — единственный тест не про функцию:** он поднимает настройки развёртывания и проверяет,
что у каждого driven-порта есть адаптер. Без реализации остаются ровно два порта, и оба намеренно:
`ProviderProbePort` (задел, для SMS его не будет) и `AudienceResolverPort` (FR-8.11 вне объёма). Третий уронит
сборку, пока у него не появится адаптер, — так отсутствие бина перестаёт быть открытием в проде.

**Chaos использует `docker pause`, а не стаб** (QA-06): испытывать нужно **зависшее** соединение, а не
отказанное — второе ловится таймаутом тривиально, первое и вызывает инциденты. Тест, поставивший общий контейнер
на паузу, снимает её в `@AfterEach`, а помощник идемпотентен, поэтому уборка не падает на контейнере, который
никогда не ставили на паузу.

**Совместимость контрактов (NF-08) — рукописный список полей** в `OutboundContractCompatibilityTest`. Кодек и
лежащая рядом схема двигаются вместе, поэтому только замороженная копия заметит переименование, которое сломало
бы всех потребителей в Банке.

**Тег `integration` отделяет то, чему нужен Docker**: такие тесты исключены из `test` и идут только через
`./gradlew integrationTest`; имя класса заканчивается на `IT`.

**Журнал аудита нельзя очистить** — БД запрещает `UPDATE`, `DELETE` и `TRUNCATE` (V7). Журнал, который может
очистить тест, может очистить и администратор. Поэтому тесты аудита написаны так, чтобы быть безразличными к
тому, что в журнале уже есть.

**Фронт — два уровня** (QA-07): Vitest + Testing Library в jsdom и Playwright для четырёх сценариев приёмки
(пауза батча, повтор из DLQ, публикация шаблона, тестовая отправка) плюс чтение отказа BFF. Backend в E2E
намеренно не поднимается: BFF застаблен на уровне сети с живым состоянием (пауза меняет статус карточки, повтор
убирает строку), панель работает в открытом режиме — поведение самого Модуля проверяют его интеграционные тесты.
Стаб обязан устанавливаться **до** `initApi`, потому что openapi-fetch захватывает `globalThis.fetch` в момент
создания клиента (`mockApi` пересоздаёт его, поэтому порядок нельзя перепутать).

**Нагрузочные сценарии (QA-05) Gradle не запускает** — им нужен контур, а не ноутбук: `load/k6/` плюс README с
предусловиями и требованиями к отчёту приёмки.

## Альтернативы

- **Один ArchUnit-класс со всеми правилами.** Падение перестаёт объяснять, что именно нарушено.
- **Тестировать зависшего провайдера стабом с задержкой.** Не воспроизводит поведение сокета и пула соединений.
- **Проверять совместимость контрактов сравнением с текущей схемой.** Схема двигается вместе с кодом, поэтому
  такая проверка всегда зелёная.
- **Поднимать backend в E2E.** Превращает тест панели в тест всего и делает его нестабильным по чужим причинам.

## Последствия

**Положительные.** По имени упавшего теста понятно, какое правило нарушено. Обычная сборка не требует Docker.
Ломающее изменение публичного контракта невозможно сделать незаметно.

**Цена.** Замороженный список полей нужно осознанно обновлять при намеренном изменении контракта — это и есть
момент, когда стоит подумать о потребителях. Тесты, безразличные к содержимому журнала аудита, чуть многословнее.

## Как нарушение будет замечено

`./gradlew build` и `./gradlew integrationTest`. Со стороны фронта — `npm test` и `npm run test:e2e`
(последнему нужен разовый `npx playwright install chromium`).
