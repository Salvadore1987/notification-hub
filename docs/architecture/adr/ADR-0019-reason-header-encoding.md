# ADR-0019. Обоснование действия едет в заголовке в виде percent-encoded UTF-8

| | |
|---|---|
| **Статус** | Принято · реализовано |
| **Дата** | 09.08.2026 |
| **Требования SRS** | FR-7.3, SEC-03, §8.2 |
| **Связанные решения** | [ADR-0017](ADR-0017-admin-bff-separate-api.md), [ADR-0033](ADR-0033-frontend-stack.md) |

## Контекст

FR-7.3 требует журналировать, кто и что сделал, а SEC-03 — сопровождать критичные операции подтверждением.
Обоснование оператора («разобрано вручную», «ложное срабатывание») передаётся в заголовке `X-Commhub-Reason`,
чтобы не менять тело каждой команды.

При тестировании фазы 18 выяснилось, что **русское обоснование не покидало браузер**: значение HTTP-заголовка —
это байтовая строка, и `X-Commhub-Reason: разобрано вручную` роняет запрос при его сборке. Операция при этом
выглядела для оператора как сетевая ошибка неизвестного происхождения.

## Решение

Заголовок кодируется как percent-encoded UTF-8 и декодируется на входе:

- **Формирование — в одном месте** во фронте: `web/src/shared/reason.ts`. Не в каждом экране, иначе следующий
  экран снова соберёт заголовок руками.
- **Декодирование — один раз на входе**: `adapter/in/admin/support/ReasonHeaderFilter`.
- **Только админский BFF.** Заголовок `/api/v1` из §8.2 — опубликованный контракт, и менять его правила
  кодирования нельзя: интеграции Банка написаны под то, что там сейчас.

Соглашение фронта: `null` из диалога обоснования означает «оператор отменил действие», пустая строка — «оператор
подтвердил без обоснования». Это разные вещи, и путать их нельзя (`useReasonPrompt`).

## Альтернативы

- **Base64 в заголовке.** Работает и делает журнал нечитаемым при просмотре сырых запросов; percent-encoding
  остаётся глазами читаемым для латиницы и стандартен.
- **Перенести обоснование в тело запроса.** Требует поля в каждой команде, включая те, у которых тела нет
  (`POST …/actions/pause`).
- **Разрешить только латиницу.** Оператор пишет по-русски; ограничение переносит проблему на человека.

## Последствия

**Положительные.** Обоснование доезжает и попадает в неизменяемый журнал. Правило кодирования существует в двух
файлах — по одному на сторону, — а не в каждом экране.

**Цена.** Ещё одно место, о котором нужно знать при добавлении экрана с обоснованием; смягчается тем, что
экраны используют общий хук, а не собирают заголовок сами.

## Как нарушение будет замечено

Компонентный тест проверяет и отправленный запрос, и то, что увидел оператор (стаб BFF записывает отправленное).
E2E-сценарий повтора из DLQ идёт с кириллическим обоснованием.
