# Диаграммы C4 (LikeC4)

Модель архитектуры Модуля в формате [LikeC4](https://likec4.dev) — «диаграммы как код»:
одна модель, из неё генерируются все представления, поэтому схемы не расходятся между собой.

## Файлы

| Файл | Содержание |
|---|---|
| `specification.c4` | Виды элементов (`actor`, `system`, `container`, `component`, …), теги ролей в гексагоне, виды связей |
| `model.c4` | Сама модель: акторы §2.3, внешние системы §9, контейнеры Модуля и компоненты backend (компонент = Gradle-модуль) |
| `views.c4` | Представления: три контекстных, контейнерное, четыре компонентных и четыре динамических |

## Представления

| Представление | Уровень C4 | О чём |
|---|---|---|
| `index` | L1 | Контекст: акторы, Модуль, внешние системы |
| `ingressContext` | L1 | Приём рассылок и обратный поток статусов |
| `providerContext` | L1 | Провайдеры каналов доставки |
| `containers` | L2 | SPA, backend, PostgreSQL; Kafka — снаружи, это кластер Банка |
| `components` | L3 | Гексагон целиком: driving-адаптеры → ядро → driven-адаптеры |
| `componentsIngress` | L3 | Приём: REST, Kafka, callback, общий разбор IK-03 |
| `componentsDelivery` | L3 | Доставка: канальные порты и провайдерные адаптеры |
| `componentsState` | L3 | Состояние, outbox, метрики и логи |
| `otpFlow` | dynamic | OTP от REST-запроса до передачи провайдеру (SLA TC-01) |
| `statusFlow` | dynamic | DLR провайдера → канонический статус → Kafka источнику |
| `failoverFlow` | dynamic | Таймаут провайдера → breaker → failover на резервного |
| `adminFlow` | dynamic | Оператор ставит батч на паузу (сценарий QA-07) |

## Как смотреть

```bash
# интерактивный просмотр с горячей перезагрузкой (http://localhost:5173)
npx likec4 start docs/architecture/c4

# статический сайт
npx likec4 build -o docs/architecture/c4/dist docs/architecture/c4

# картинки для протоколов и презентаций
npx likec4 export png -o docs/architecture/c4/out docs/architecture/c4

# проверка модели (полезно в ревью)
npx likec4 validate docs/architecture/c4
```

В VS Code — расширение **LikeC4** (подсветка, автодополнение и предпросмотр прямо в редакторе).

Каталоги `dist/` и `out/` — артефакты сборки, в git не коммитятся.

## Соглашения модели

- **Идентификаторы — на английском, как в коде; заголовки и описания — на русском** (правило проекта:
  документация RU, код и контракты EN).
- **Компонент = Gradle-модуль.** Так диаграмма L3 не расходится с `settings.gradle.kts`: появился адаптер —
  появился компонент, и наоборот.
- **Каждый элемент несёт ссылку на требование SRS**, по которому он существует (`AR-04`, `PU-06`, `EM-02` …).
  Требования расшифрованы в [`../FR.md`](../FR.md) и [`../NFR.md`](../NFR.md), решения — в [`../adr/`](../adr/).
- **Теги** `#driving`, `#core`, `#driven`, `#neither` фиксируют роль компонента в гексагоне: направление
  зависимостей на схеме должно совпадать с тем, что проверяет ArchUnit (AR-03).
- Kafka — внешняя система: корпоративный кластер Банка не входит в поставку Модуля.
- Иконки (`icon tech:kafka` и т. п.) намеренно не проставлены — они тянут за собой пакет `@likec4/icons`;
  добавляются одной строкой в элемент, если решим собирать презентационные схемы.
