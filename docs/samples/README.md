# Образцы файлов

Готовые файлы к экранам панели, которые принимают загрузку. Формат каждого описан там, где он
применяется, — здесь лежит то, что можно перетащить в форму и увидеть результат, не набирая CSV
руками.

## `recipients-sms-ru.csv` — список получателей рассылки

К экрану «Отправка» → «Рассылка из файла» (`docs/ADMIN-GUIDE.md`, §2а). Сделан под то, что
поднимается локальным `docker compose`: канал **SMS**, шаблон **`GREATING`** локали **RU** с
единственной переменной `NAME`. 50 строк.

Колонки: `msisdn`, `clientId`, `externalId` — служебные; **`NAME` — merge-переменная**, потому что
переменной считается любая колонка, кроме служебных, а имя переменной есть имя колонки, и регистр
имеет значение. Колонка `name` строчными не заполнила бы `{NAME}` — отправка ушла бы в
`TEMPLATE_VARIABLE_MISSING`.

**Последние две цифры номера — это сценарий.** На локальном стенде отвечает не провайдер, а
`adapter/out/provider/mock` (ADR-0041), и он читает поведение из адреса. В файле:

| Суффикс | Строк | Что произойдёт |
|---|---|---|
| `00` | 40 | принято, отчёт `DELIVERED` |
| `01` | 7 | принято, отчёт `UNDELIVERED` |
| `04` | 3 | адрес непригоден: Hub заносит его в suppression-лист (FR-5.1) |

**Суффиксов `02` и `03` в образце нет намеренно.** `02` — «провайдер не ответил»: строка уходит в
ретраи и в DLQ. `03` — блокирующий отказ (§18.1, код 102), он открывает circuit breaker провайдера,
и одна такая строка остановит остаток рассылки. Оба сценария стоит проверять отдельно и осознанно, а
не получать их в файле, которым проверяют обычную рассылку.

**У пяти строк пуст `externalId`** — тоже намеренно. Строка без него берёт идентичность из
`sha256(файла)` и номера строки, поэтому повторная загрузка того же файла в окне дедупликации даёт
`DUPLICATE`, а не второе SMS каждому клиенту (FR-1.5). Загрузите файл дважды — это видно на
счётчиках рассылки.

Кодировка — UTF-8 с BOM, как у выгрузок панели: Excel открывает кириллицу без плясок, а Hub BOM у
первого заголовка снимает сам.

Проверить файл, ничего не отправляя (сметa не отправляет и обоснования не требует):

```bash
TOKEN=$(curl -s -d grant_type=password -d client_id=commhub-admin -d username=demo -d password=demo \
  http://localhost:8180/realms/commhub/protocol/openid-connect/token \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')

curl -s -X POST 'http://localhost:8080/api/admin/v1/send/estimate?streamId=mobile-app&templateCode=GREATING&locale=RU&channel=SMS' \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: text/csv' \
  --data-binary @docs/samples/recipients-sms-ru.csv
```

Ответ на развёрнутом стенде: `recipients: 50`, `segments: 50`, `provider: "PM"`, `rejection: null`,
пустые `missingVariables` и `failures`. Пустой `missingVariables` — и есть доказательство, что
заголовок совпал с переменной шаблона по регистру.

Если пришло `NO_ROUTE_AVAILABLE / channel SMS is not configured` — на контуре не заведён профиль
канала: «Каналы и провайдеры» → «Каналы» → «Настроить» у SMS, с непустым порядком fallback.
